# Driver Run UI-API QA Checklist

## Scope
- 대상: `오더 보드(마켓)` -> `추천 오더 상세/오더 상세` -> `운임 제안/배차 수락` -> `운행 탭`
- 목적: 상태 동기화, 중복 클릭 방지, 실패 재시도 가능 여부 확인

## 시나리오 A: 운임 제안
1. 오더 보드에서 추천 노선 또는 단건 오더 상세로 진입한다.
2. `운임 제안` 버튼 클릭 후 모달에서 금액/사유를 제출한다.
3. 제출 중 버튼이 로딩/비활성화되고 중복 제출이 차단되는지 확인한다.
4. 성공 시 상세/목록 상태가 즉시 갱신되는지 확인한다.
5. 실패 시 에러 문구가 표시되고 다시 제출 가능한지 확인한다.

## 시나리오 B: 배차 수락
1. 노선 상세에서 `배차 수락`을 누른다.
2. 수락 처리 중 CTA가 로딩/비활성화되는지 확인한다.
3. 성공 시 `운행 탭`으로 이동하고 수락 오더가 운행 상태로 분류되는지 확인한다.
4. 다건 수락 시 성공/실패 건수가 메시지에 정확히 반영되는지 확인한다.

## 시나리오 C: 실패/경합
1. 동일 오더를 빠르게 연타해 중복 호출이 발생하지 않는지 확인한다.
2. 409(이미 수락됨) 응답 시 사용자에게 명확한 안내가 노출되는지 확인한다.
3. 일반 네트워크 실패 시 `다시 시도` 버튼으로 즉시 재시도 가능한지 확인한다.

## 회귀 체크
- 추천 오더 상세의 3D 적재 시뮬레이션이 다건 기준으로 모두 표시되는지 확인한다.
- 오더 보드 카드에서 `운임 제안`/`배차 수락` 동시 실행이 차단되는지 확인한다.
- 수락/제안 후 `추천 목록`, `오더 상세`, `운행 탭` 데이터가 모두 갱신되는지 확인한다.
