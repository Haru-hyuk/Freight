# Database Table Reference

이 문서는 Freight 백엔드의 주요 테이블 역할을 빠르게 파악할 수 있도록 정리한 문서입니다.
컬럼 전체 사양보다는 "이 테이블이 왜 존재하는지"와 "어디에 쓰이는지"를 중심으로 설명합니다.

## 사용자/인증

### `admins`
- 관리자 계정을 저장하는 테이블입니다.
- 운영자, 고객센터, 슈퍼관리자 권한과 로그인 이력을 관리합니다.
- 공지 등록, 승인/제재 처리, 운영 화면 접근의 주체가 됩니다.

### `drivers`
- 기사 회원 기본 정보를 저장합니다.
- 연락처, 주소, 정산 계좌, 인증 상태, 현재 선택 차량, 근무 상태 등을 포함합니다.
- 운송 수행, GPS 공유, 정산, 기사 전용 기능의 기준 테이블입니다.

### `shippers`
- 화주 회원 정보를 저장합니다.
- 회사명, 사업자 정보, 연락처, 선결제 잔액, 누적 주문 수 등을 관리합니다.
- 견적 등록, 결제, 운송 요청, 정산 확인 기능의 기준이 됩니다.

### `jwt_refresh_tokens`
- 로그인 세션 유지를 위한 리프레시 토큰 저장 테이블입니다.
- 사용자 유형, 사용자 ID, 해시된 토큰, 만료 시간, 폐기 여부를 관리합니다.
- 다중 디바이스 로그인과 토큰 회수 처리에 사용됩니다.

### `push_devices`
- 푸시 알림을 보내기 위한 디바이스 정보를 저장합니다.
- 사용자 유형별로 FCM 토큰, 디바이스 종류, 활성 상태를 관리합니다.
- 기사/화주/관리자 알림 발송 대상 조회에 사용됩니다.

## 견적/운송 요청

### `quotes`
- 화주가 등록한 운송 요청의 메인 테이블입니다.
- 출발지/도착지 주소, 좌표, 화물 정보, 희망 운임, 최종 운임, 차량 조건, 상태를 저장합니다.
- 견적 등록, 수정, 조회, 매칭, 운송 상태 표시의 중심 테이블입니다.

### `quote_stops`
- 하나의 견적에 포함된 경유지/정차 지점을 저장합니다.
- 순번, 주소, 좌표, 담당자 정보, 시간창(window) 정보를 가집니다.
- 다중 경유 운송, 경로 계산, 배차 추천에 활용됩니다.

### `quote_checklist_items`
- 견적에 선택된 부가 체크리스트 항목을 저장합니다.
- 예를 들어 상하차 옵션, 추가 작업, 특수 요청과 그에 따른 추가 요금을 기록합니다.
- 견적 추가 비용 계산과 상세 화면 표시에 사용됩니다.

### `checklist_items`
- 화주가 견적 작성 시 선택할 수 있는 체크리스트 마스터 데이터입니다.
- 항목명, 아이콘, 추가 요금 여부, 입력 필요 여부, 정렬 순서를 관리합니다.
- 견적 작성 UI와 운임 계산 로직의 기준값이 됩니다.

### `shipper_addresses`
- 화주의 자주 쓰는 주소록 테이블입니다.
- 기본 주소 여부, 라벨, 상세 주소, 메모를 저장합니다.
- 견적 등록 시 출발지/도착지 자동완성과 빠른 입력에 사용됩니다.

### `geocoding_cache`
- 주소를 좌표로 변환한 결과를 캐시하는 테이블입니다.
- 정규화된 주소, 위도/경도, 해석된 주소, 만료 시각을 저장합니다.
- 같은 주소에 대한 반복 지오코딩 호출을 줄이고 응답 속도를 높입니다.

### `route_distance_cache`
- 경로 거리 계산 결과를 캐시하는 테이블입니다.
- 좌표 조합 기반 키, 지점 수, 거리, 만료 시간을 저장합니다.
- 운송 거리 계산, 예상 운임 계산, 경로 추천 시 외부 API 호출을 줄이는 데 사용됩니다.

## 매칭/운송 진행

### `matches`
- 견적과 기사를 연결하는 매칭 테이블입니다.
- 어떤 기사(`driver_id`)가 어떤 견적(`quote_id`)을 수락했는지와 현재 운송 상태를 기록합니다.
- 수락 여부, 수락 시각, 위치 공유 여부, 그룹 운송 키, 낙관적 락용 버전 값 등을 관리합니다.

### `driver_routes`
- 기사 기준 추천/운행 경로 정보를 저장하는 테이블입니다.
- 출발지/도착지, 경유 정보(JSON), 예상 수익, 잔여 적재 용량, 좌표, 상태를 담습니다.
- 복귀 노선 추천, 합짐 추천, 기사 오더보드 계산 결과 저장에 활용됩니다.

### `route_recommendation_feedback`
- 추천 경로에 대한 후속 결과를 기록하는 피드백 테이블입니다.
- 추천 점수, 실제 수락 여부, 정시 완료 여부, 취소 여부, 실현 수익 등을 저장합니다.
- 추천 알고리즘 보정과 품질 평가 데이터로 사용됩니다.

### `gps_logs`
- 운행 중 기사 위치 이력을 저장합니다.
- 좌표, 속도, 방향, 경로 이탈 여부, 기록 시각을 관리합니다.
- 화주 실시간 위치 조회, 관리자 관제, GPS 이력 분석의 기반이 됩니다.

### `delivery_photos`
- 기사가 상차/하차 시 업로드한 사진을 저장합니다.
- 사진 유형, 파일 URL, 촬영 시각, 촬영 좌표, 용량, MIME 타입 등을 담습니다.
- 운송 증빙, 화주 확인, 분쟁 대응 자료로 활용됩니다.

### `notifications`
- 매칭, 결제, 운송 상태 변경 등에 대한 알림 저장 테이블입니다.
- 수신자, 수신자 유형, 메시지, 읽음 여부, 매칭 연결 정보를 관리합니다.
- 앱 내 알림함과 운영 알림 기록에 사용됩니다.

## 결제/정산

### `payments`
- 화주 결제 내역을 저장합니다.
- 결제 수단, 상태, 결제 시각, PG 참조값, 총 결제 금액 등을 기록합니다.
- 결제 완료 후 정산 생성, 결제 상태 조회, 환불 흐름의 기준이 됩니다.

### `settlements`
- 운송 1건에 대한 정산 정보를 저장합니다.
- 총 운임, 플랫폼 수수료, 긴급료, 기사 지급액, 결제 상태, 정산 상태, 검토 메모 등을 담습니다.
- 화주 결제 완료 이후 기사 정산과 관리자 승인 흐름을 담당하는 핵심 테이블입니다.

### `driver_daily_stats`
- 기사의 일자별 운행 통계 요약 테이블입니다.
- 총 운행 건수, 거리, 매출, 순이익, 플랫폼 수수료, 유류비를 집계합니다.
- 기사 대시보드와 정산 요약, 통계 화면에 활용됩니다.

## 차량/적재

### `trucks`
- 기사가 등록한 실제 차량 정보를 저장합니다.
- 톤수, 차종, 적재함 크기, 보험, 주행거리, 승인 상태, 심사 메모를 관리합니다.
- 기사 활동 전 차량 승인, 적재 계산, 오더 추천, 배차 가능 여부 판단에 사용됩니다.

### `truck_spec_catalog`
- 차종별 표준 차량 제원을 저장하는 기준 테이블입니다.
- 적재함 길이/너비/높이, 최대 중량, 최대 부피, 팔레트 수, 도어 위치 등을 제공합니다.
- 기사 차량 등록 자동 보정, 3D 적재 시뮬레이션, 추천 계산의 참조 데이터입니다.

### `load_plans`
- 적재 계획 실행 결과의 헤더 테이블입니다.
- 어떤 트럭에 대해 적재율, 총 중량, 적재 성공 개수, 미적재 개수, 위반 횟수가 나왔는지 저장합니다.
- 추천 상세, 3D 적재 시뮬레이션, 적재 검증 기록에 사용됩니다.

### `load_plan_items`
- 개별 화물이 적재 계획 안에서 어떻게 배치되었는지 저장합니다.
- 화물 크기, 무게, 하차 순서, 회전 가능 여부, 적재 위치 좌표, 배치 결과를 담습니다.
- 적재 시뮬레이션 시각화와 적재 실패 원인 분석에 활용됩니다.

### `surcharge_option_vehicle_rates`
- 추가 요금 옵션의 차량별 가중치/추가 금액을 저장합니다.
- 특정 옵션이 차량 종류에 따라 얼마가 더 붙는지 관리합니다.
- 운임 산정에서 차량 타입별 surcharge 계산에 사용됩니다.

## 운영/관리

### `announcements`
- 관리자 공지사항 테이블입니다.
- 제목, 내용, 상단 고정 여부, 게시 시각을 저장합니다.
- 기사/화주 앱 공지 영역과 관리자 공지 관리 화면에 사용됩니다.

### `inquiries`
- 기사와 화주의 문의 내역을 저장합니다.
- 작성자 유형, 제목, 내용, 답변 상태, 관리자 답변, 답변 시각을 관리합니다.
- 1:1 문의 기능과 고객센터 응대 이력 관리에 사용됩니다.

### `sanction_events`
- 운영자가 사용자에게 적용한 제재 내역을 저장합니다.
- 제재 대상, 대상 역할, 제재 유형, 사유, 금액, 상태를 기록합니다.
- 운영 감사 로그와 제재 이력 조회에 활용됩니다.

## 테이블 관계 요약

- `shippers` 1:N `quotes`
- `quotes` 1:N `quote_stops`
- `quotes` 1:N `quote_checklist_items`
- `quotes` 1:1 또는 1:N 관점으로 `matches`
- `matches` 1:1 `payments`
- `matches` 1:1 `settlements`
- `matches` 1:N `gps_logs`
- `matches` 1:N `delivery_photos`
- `drivers` 1:N `trucks`
- `drivers` 1:N `driver_routes`
- `trucks` 1:N `load_plans`
- `load_plans` 1:N `load_plan_items`

## 핵심 흐름

### 1. 견적 생성
- 화주가 `quotes`를 생성합니다.
- 경유지가 있으면 `quote_stops`에 저장합니다.
- 주소 좌표화 결과는 `geocoding_cache`를 참고하거나 갱신합니다.

### 2. 매칭 및 운송
- 기사가 수락하면 `matches`가 생성/갱신됩니다.
- 운행 중 위치는 `gps_logs`, 증빙 사진은 `delivery_photos`에 쌓입니다.

### 3. 결제 및 정산
- 화주 결제는 `payments`에 저장됩니다.
- 결제 완료 후 `settlements`가 생성되고, 관리자 승인 이후 최종 상태가 확정됩니다.

### 4. 추천 및 적재
- 차량 기준 정보는 `truck_spec_catalog`, 실제 차량은 `trucks`를 사용합니다.
- 적재 결과는 `load_plans`, `load_plan_items`에 저장됩니다.
- 추천 결과와 성능 평가는 `driver_routes`, `route_recommendation_feedback`로 이어집니다.
